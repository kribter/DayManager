> 更新于 2026-11-21（同步三批修复的状态）。来源：11-17 讨论「只是单纯接入 AI 能力不太够，后续应该要变成 agent」。

> 末尾第九节是一份**攒批的 bug 台账**（原始实例登记 + 状态标记），与路线分开看。
> 11-21 用户发起修了两批：时间观念族（`Core/Ai/ChatTime`）与视野 / 查询
> （默认带过去 7 天回顾 + 只读 `query` 真两轮）。下文二、三、四、七、九节已同步到 11-21 的实际情况；
> 路线与方向本身没有改动。

## 一、先校准：它现在已经是 agent 了

现在对话里的 AI 有五个**写**工具（create / set_status / reschedule / rename / delete），
能真的改数据，改完整批可撤销；11-21 又加了第六个动作 `query`（只读、查窗口外某天、
不进执行器也不进撤销批次）。这不是「接入了 AI 的日程软件」，这就是 agent——
只是最简单的那种。

所以问题从来不是「要不要变成 agent」，而是**成熟到哪一级**。分级不是理论，
每一级都对应能做/不能做的具体事。

## 二、实测暴露的毛病（「一定要有的能力」从这些里来）

下面每条都是真实发生过的，不是猜的。**一份必备能力清单，应该从毛病里长出来，
而不是从「agent 应该很厉害」里推出来。**

| # | 毛病 | 实例 | 说明的能力缺口 |
|---|---|---|---|
| 1 | AI 心算时间差会错 | 10-31 23:49 说「十点差十分」，应为十二点差十分 | 硬数字不能让它自己算 |
| 2 | 承诺悬空 | 11-05 起连续 11 天零动作批次，AI 反复说「我记着要标掉」，没有任何机制存这句话 | 说到做不到——语言的手做了承诺，数据的手没有去处 |
| 3 | 同一句复读 | 「考完就翻篇喵今晚一条不排」跨四天发了至少 5 遍 | 没有「这句说过没有」的闸 |
| 4 | 听不懂拒绝 | 「数据库那条标不标」追问 4 遍，用户用「笨猫」岔开它没听懂 | 不会读「不想谈这个」 |
| 5 | 只能整批退 | 要改 5 件事，第 3 个失败，前两个已落库，只能整批撤销重来 | 失败了没法只重做那一步 |
| 6 | 知道也推不动 | 11-17 晚：18:03 用户说「去吃饭」，20:10 AI 还在说「饭先吃」——而提示词里**当时时间、人正在电脑前、聊天历史全都喂了**（ProactiveService 520/379/121 行） | 信息给了 ≠ 它会用：该代码做的推理（距上次对话多久、状态是否过期）留给了模型，而模型推时间已有两次前科 |
| 7 | 视野里没有「过去」 | 11-17 深夜：用户问昨天的事，AI 答「看不到昨天的任务」——**当时它说的是实话**。上下文 = 今天 + 未来 7 天（AgentService 取数只有这两段），五个工具全是写操作、没有任何「查」 | 「用户能看到的 AI 都能看到」这条原则**当时**确实没实现：界面能翻任意一天，AI 是白名单视野。注释里修「看不到明天」的动机写得清清楚楚，对称的「昨天」压根没进设计。**11-21 已修**：默认带过去 7 天回顾 + 只读 `query` 查窗口外，见第九节 |

> 里「隔了多久、状态是否过期」这一半已由 `ChatTime` 交给代码算，其余（状态过期标记）
> 仍未动；#2、#3、#4、#5 未动。上表是**历史实例**，是能力清单的来源，不因修了就抹掉；

## 三、四级阶梯

```
L0  单轮工具调用     说一句 → 调一次工具 → 整批执行 → 整批撤销        ← 主体仍在这（11-21）
L1  多轮闭环         工具结果回喂给它；能"先看看再决定"；失败只重做那一步
L2  承诺与待办       它说"我记着"，就真的落一条；下次开口前先翻账
L3  主动执行         不等叫，按时间/事件自己发起行动（现在是"只说话不动手"）
```

> **11-21 的位置**：聊天链路打通了 L1 的第一道门——模型发只读 `query` → 系统查库 →
> 结果回喂 → 再答（最多两轮）。但 L1 其余三件（分步做、失败只重做那一步、撤销从整批
> 变按步）都还没动，**所以整体仍算 L0**，别把「能查两次」当成进了 L1。主动开口链路
> 仍是单轮。

**每一级能做什么是硬边界**：L1 才接得住「把这周的安排重排一下，冲突的往后挪」
（它得先看现状、分步改、错了改那一步）；L2 才接得住「帮我记着这事」；
L3 才接得住「发现你连着三天没动那个任务，我把它的提醒往前挪了」。

## 四、必备能力清单（按「哪级必须」分组）

### 底线 —— 不管到哪级都必须修牢（现在的缺口，都是小改）

1. **硬数字代码算。** 时间差、时长、完成率，全部由代码算好喂给它，
   提示词里只许它复述、不许它推算。已定案（2026-11-02 复盘）；**时间这一族 11-21 已落地**：
   `Core/Ai/ChatTime` 把时段 / 日期标签 / 间隔 / 跨夜全算好，聊天与主动开口两条链路
   共用一份口径；完成率与时长本来就是代码算的（stats）。剩下的推广（所有数字都守住
   这条）与口径统一见第六节。
2. **说过没的闸。** 每句主动开口落库前查一遍近期是否说过同句/同义，
   防复读。晚间总结已有这个闸（AiDailySummary），模板句没有。
3. **听得懂拒绝。** 用户岔开话题 = 这个话题的追问到此为止；
   明示「不想谈」= 当天不再提。这条要写进提示词硬规矩。

### L1 多轮闭环 —— 结构上最大的一步

4. **先读后写。** 改东西之前先查现状（这周有什么、那天有没有空位），
   而不是只靠提示词里喂的静态上下文。11-21 有了 `query` 能查窗口外某天的清单，
   但「查完再动手改」的完整闭环还没验证，撤销也仍按整批。
5. **分步做，失败续做。** 复杂操作拆成步，逐步落库逐步汇报；
   第 N 步失败只重做第 N 步，撤销从「整批」变「按步」。
   ——撤销模型是 L1 里工程量最大的部分。

### L2 承诺与待办

6. **承诺落账。** AI 说「我记着 / 我明天提醒你 / 到时候我帮你标掉」，
   就真的落一条待办记录（一张小表），它自己写的，用户可看可删。
7. **开口前翻账。** 下次开口前先查自己的待办账，该兑现的兑现、
   过期的说明。这条直接治毛病 #2。

### L3 主动执行

8. **权限边界。** 哪些动作它可以自己做完再报、哪些必须先问再做。
   这条不先定，L3 就会变成「悄悄改我的数据」。既有底线全部继承：
   AI 不能真删、可撤销、防过量时提异议等二次确认。
9. **主动发起。** 触发条件已经有纯函数底子（ProactiveDecider），
   欠的是「从说话到动手」这一段，以及画像三出口的③（触发读画像）还没接。

## 五、每级的代价（决定「一口气上多少」时要看的）

| 级 | 要动什么 | 代价 |
|---|---|---|
| L0 底线三件 | 提示词拼装 + 开口闸 + 少量代码 | 小，各自可独立验证 |
| L1 | AgentService 改多轮循环；撤销模型批次→按步 | **大**：每轮 token 涨、要能解释「它为什么这么做」、半途失败的状态一致性 |
| L2 | 新一张小表 + 开口前查询 | 中：要防它乱记一堆，承诺要有格式和上限 |
| L3 | 权限矩阵 + 主动行为从「说」到「做」 | 中偏大：信任问题，出一次错代价高 |

**不变量（任何一级都不许破）**：不阻断、不改考核、一切可撤销、AI 不能真删、
用画像做减法不做审判。

## 七、感知与记忆：另一条轴（2026-11-17 讨论定稿）

> 四级阶梯说的是「它能做到多复杂」，这一节说的是「它知道得多全」。
> 两条轴纵横关系，不重叠。**当前状态：主体仍是讨论存档、未排落地**（11-21 例外：
> 用户发起做了「自查」里最窄的一小块——只读 `query` 查任务清单）——攒够了或
> 某条确定要做时，再由用户发起，逐条落实。

用户对「AI 一定要有的 skill」的定稿三条 + 讨论后补入的两条，五项能力
其实是**同一条河的上中下游**，不是五个孤立功能：

```
搜索 / 读文件 / 自查   →   记忆   →   兑现
（把信息喂进来）          （把信息留下来）  （把信息变成行动）
```

### 1. 联网搜索【已定】
拆任务的依据需要外部的新信息——「现在学 X 该用什么材料、走什么路线」，
模型内部知识是旧世界，不联网就只能编。
性质上是工具列表的自然扩展（现有五个写工具 + 一个只读 `query`，再加一个搜索）。
**悬着的一个决策点**：搜索是另一个服务、另一份 key，接哪家、
花钱的动作要不要先确认——到落实时再定。

### 2. 读文件【已定】
pdf / docx 等作为「用户想让 AI 知道的东西」的入口——比如把项目结构
文档给它，让它据此拆大任务。这直接补「拆解带 guess 预填」那条的老病根：
**guess 之所以是 guess，就是因为缺依据**。

### 3. 记忆【已定；分层写法取倾向】
从聊天记录 / 任务记录里**自动沉淀**有价值、有情感的信息，供后续使用。
和画像的分工要分清——**画像存数字，记忆存语义条目**：
「他的目标是 X 考试」「上次考完是他自己来报喜的」这类话，
现在没有任何地方存，每次对话它都是陌生人（11-16 翻库可见这类信息密度不低）。

**分层（长 / 中 / 短）**：方向已定，写法倾向——**「长短中」是规则算出来的
结果，不是入库时手选的标签**。每条记忆存的时候带结构化信息（发生了什么、
什么时候、依不依赖某个进行中的事），然后：
- 短期 = 按天自然过期——**这层不重建**，对话历史 + 日结已在干这件事
- 中期 = 跟着事件结束失效（「备考 11 月」考完作废）
- 长期 = 基本不删，但能被新事实**顶掉**（「换目标」是改写不是追加）

分层的真正用处是**每一层配一个不同的「什么时候不算数」**——
与画像「结论现算不存、防固化」同一条原则。

三条硬规矩（落实时必须带上）：谁来筛（模型自判会记垃圾也会漏，
要有筛选标准 + 条数上限）；**可看可删可纠正**（记的是关于你的话）；
过期机制。

### 4. 自查【讨论后补入】
与搜索正好一对：**搜索查外部世界，自查查你自己的世界**——
时间账、画像、真实可用时段都在库里，但它现在只能被动等提示词喂。
能自己查，拆出来的任务才贴「过去一周你 22 点后才有空」的真实情况，
而不是贴「每天两小时」的美好愿望。
**实证已到第三个**：毛病 #7（问昨天答不出——连「过去」都不在视野里）、
#6（吃饭事件——时间账明明证明人回来了）、外加拆解不看历史。

**11-21 开了第一道门**：只读 `query` 让聊天链路能自己查窗口外某一天的**清单**，
查库结果回喂后再答。但这一节说的「查时间账、查画像、查真实可用时段」还做不到——
`query` 只查 items，其余三项仍在讨论存档里。

### 5. 兑现【讨论后补入】
记忆的下半身：**记得 ≠ 做到**。光有记忆，它只是「很懂你但什么都不做」——
懂你成了聊天的调料。「我记着帮你标掉」要真的变成记下来 + 到期动手，
这条和阶梯的 L2/L3 是同一段路。

---

### 毛病 #6（吃饭事件）为什么值得留着当例子

它一次命中本节三处：**记忆**（「去吃饭」这个状态过期两小时没人标失效——
分层说的「什么时候不算数」缺的正是这个）、**自查**（时间账明明证明人回来了，
它没用）、底线三件（同主题三遍没闸、时长差留给它心算）。
根子一句话：**不是它不知道，是知道也推不动——该代码做的推理留给了模型。**

## 八、顺序建议（11-17 更新）

底线三件（1–3，毛病 #6 又添了两条实证）→ 口径统一 → 第七节的感知/记忆轴
与 L1 并行推进（自查、兑现分别是 L1「先读后写」和 L2「承诺落账」的感知侧）→ L3。

> 第七节五项能力**不改变阶梯顺序**，它们让每一级更值得做：
> 没有搜索和自查，L1 的「先看看再决定」看的是旧世界；
> 没有记忆，L2 的「说到做到」没有账可记。
>
> 老理由仍然成立：底线三件便宜且立刻止血；L1 是分水岭但依赖可信数据；
> L2 在 L1 之后做才不用返工；L3 最贵的是信任，放在用户已经见过
> 它「说到做到」之后。
