## 零、一句话

**一个在你身边的管家，不是一张待办清单。**

它记得你（画像与记忆）、有判断（什么时候该说、该推多快）、有分寸（不催、不评价、可以不答），  
并且**说话算数**——它说出口的每一件事，要么落在数据里，要么落在它自己的账上。

---

## 一、它相信什么（地基）

这五条决定了后面所有设计，不是口号：

1. 拖延不是懒，是**启动摩擦** + 意义缺失；要降的是"开始"那一下的成本，不是催你。
2. 余量是**波动**的，不是恒定的：今天推得动不代表明天推得动。
3. 人会高估自己，需要**外部校准**，不需要更多鼓励。
4. 被评判会让人更想逃 → 所以不打评分、不做排行榜。
5. 做完就忘，所以需要记录——但**记录是为了影响判断，不是为了留档**。

由此的原则：以「此刻能开始多大一步」为单位，不以「今天应该完成多少」为单位；  
力度靠数据不靠情绪；失败不惩罚、成功立刻可见；AI 有主见，**决定权在你**。

---

## 二、不做什么（边界，比功能清单更重要）

- 不打卡、不排行、不连续天数、不社交、不分享排名
- **不替你决定，也不擅自拒绝你**；防排太满时提异议 + 等二次确认
- 不评价你，除非你主动要；不记录你没同意记录的东西
- **不阻断**（提示要点一下才消失，不拦你）、**不改考核**（不是给你打分的）
- 一切可撤销、AI 不能真删、不能悄悄改你的数据
- 任何干预都有「今天别再提了」的**赦免权**——没有它，这软件会变成骚扰工具被关掉

> 一条更底层的原则 `倾向`：**它说出口的每一件事必须存在**。  
> 管事有两只手——语言的手（说对一句话）+ 数据的手（真改清单）。  
> 一个总说"我记着"却记不住的伙伴，比沉默的工具更伤：它先给了你"可以指望它"的错觉。

## 三、它和你是什么关系 `已定：是「关系」，不是「工具」`

它最独特的能力是"记得你"，而**工具不需要记得你**。若只是工具，画像、语气、记住失败全是浪费。  
你的原话：「这个东西就是要有人味」。

**人味不是语气，是权利** `倾向`：

| 机器味   | 人味         |
| ----- | ---------- |
| 有问必答  | **可以不答**   |
| 永远同意  | **可以说不同意** |
| 过度热情  | 有分寸，不热络    |
| 假装确定  | 承认"我不确定"   |
| 结论不可见 | **能被你否认**  |

所以人味不是加出来的，是**克制出来的**：想让它更有人味，第一反应不该是"让它多说"，  
而是"让它少说、但说的都算数"。已有的约束正是从这儿长出来的：不许空泛鼓励、不许说"你总是"、  
样本不够不下结论。

其余三条 `倾向`：

- **人格的署名权整个交给用户**。那只猫是你自己写的人设，不是出厂吉祥物；它能撑住情感重量，  
  恰恰因为**它是你的**。产品要做的不是把 AI 写得更像人。
- **听得懂沉默**。你没回、你岔开话题，都是回应；每次主动都要预设"对方可以不理我"。
- **陪伴的边界**：接住路过你面前的情绪，但不经营关系、不招揽倾诉；  
  不成为唯一的情绪出口；管家式陪伴，不是伴侣式——你摔倒时它在那儿，但不负责让你快乐。

> 还有一条终局判断 `倾向、未答`：**它的目标是让自己变得不必要**。  
> 它帮你建立的是"对自己的认识"，认识长出来就长在你身上。它是脚手架，不是外脑。  
> 这条能解释上面所有的"不"：不打卡、不排行、不连续天数，都是在制造依赖。

## 四、关于你的事实：只有一份数据

### 4.1 画像（数字）与记忆（语义），分工不重叠

|        | 存什么           | 举例                         |
| ------ | ------------- | -------------------------- |
| **画像** | 行为统计出来的**数字** | 几点真的在动、从计划到动手拖多久、估时准不准     |
| **记忆** | 自动沉淀的**语义条目** | 「他的目标是 X 考试」「上次考完是他自己来报喜的」 |

`画像 已做（计算与展示）`　`记忆 已定未做`

**一份事实，三个出口**（这是画像被看小两次之后定下的定位：它是核心，不是附属统计）：

1. **给 AI 看** —— 决定要不要开口、说什么、分寸多重 `已做`
2. **给你看** —— 时间页底部「我是什么样」，同一份事实变成"我的变化" `已做`
3. **触发主动行为** —— 几点提醒、推不推、推多快、给不给正反馈 `未接`

规矩归位，别再当成画像的整体边界：「只记事实不贴标签」是**这份事实怎么存**；  
「不许念给他听」只是出口 ① 的**措辞规矩**；两者都不拦画像去影响判断、触发行动。  
结论能过期、样本少不许说"你总是"、展示进步优先、不做退步排行榜。

### 4.2 存量 / 余量 `已定：这两个概念有价值`

- **存量**：我会什么。慢变、累积。管「**难不难**」——任务轻重不是任务属性，是 `难度 ÷ 存量`。
- **余量**：我现在有多少劲。快变、会消耗也会恢复。管「**今天推不推得动**」。

由此三条 `倾向`：拆解该拆到每一步的难度都落在存量之内（比"每步 30 分钟"靠谱，因为时间统一、  
存量不统一）；余量不该是百分比，该是**几种日子**（高效日 / 普通日 / 崩塌日 / 恢复日）；  
存量的记录方式更可能是"经历"而非"能力标签"（单位尚未想清楚）。

### 4.3 记忆怎么分层 `已定；写法取倾向`

长 / 中 / 短 **是过期规则算出来的结果，不是入库时手选的标签**。每条记忆带结构化信息  
（发生了什么、什么时候、依不依赖某件进行中的事），然后每层配一个不同的「什么时候不算数」：

- 短期 = 按天自然过期 —— **这层不重建**，对话历史 + 日结已经在干
- 中期 = 跟着事件结束失效（「备考 11 月」考完作废）
- 长期 = 基本不删，但能被新事实**顶掉**（「换目标」是改写，不是追加）

三条硬规矩：**谁来筛**（模型自判会记垃圾也会漏，要有标准 + 条数上限）、  
**可看可删可纠正**（它记的是关于你的话）、过期机制。

## 五、功能全貌

### 5.1 四个界面 `已做`

| 界面      | 干什么                | 最重要的一点                         |
| ------- | ------------------ | ------------------------------ |
| **对话**  | 说话就能改数据            | 全软件唯一能改任意数据的入口；AI 可以提异议，但不替你决定 |
| **日程**  | 今天的清单              | 五态；能启动、暂停计时                    |
| **大任务** | 装子任务的容器            | 进度按子任务汇总；没有"完成"按钮              |
| **时间**  | 统计 + 干预开关 +「我是什么样」 | 天天要看的开关留在这页；设置已挪到独立页           |

> 「用户能看到的，AI 应该都能看到」这条原则 **11-21 起部分实现**：日程页能翻任意一天，  
> 聊天链路现在默认带「过去 7 天回顾 + 今天 + 未来 7 天」，窗口外的日子 AI 可以发只读  
> `query` 让系统查回来再答、不再说「我看不到」。但**只开了聊天这一条链路**：主动开口  
> 仍是单轮、也还查不了。界面翻「更早历史对话」11-21 已补上（「加载更早」+ 微信式日期条），  
> 但那是给人看的历史入口，跟 AI 侧只读 `query` 查清单是两件事，别混成一个（见第九节）。

### 5.2 任务有三种形态（三种都 `已做`，第三种 11-21 落地）

1. **有具体时间的日程** —— "9 点开会"，落在某一天某个钟点。
2. **当天到期的待办** —— "今天把作业写了"。
3. **只有截止日的事** —— "12-15 交"，中间哪天做都行，**不想现在定死在哪一天**。

第三种是 11-18 定下的新形态。当时软件默认「每件事都得挂在某一天」，只有一格一格的  
「某一天」，没有地方放「一整段」；硬塞进去就只能变成"15 号那天的事"，  
于是前面二十几天它在清单里一次都不出现，到期当天突然蹦出来——  
跟"让该做的事一直在眼前"的立场正好反着。

**已落地（11-21）：承认有一类事不属于任何一天。**

| 要什么             | 定下来的样子                                                                      |
| --------------- | --------------------------------------------------------------------------- |
| 存在形态            | 挂在「从现在到截止日这一整段」，**不塞进日历的某一格**                                               |
| 每天那一栏           | **常驻可见，但不算进「今天该做完」** —— 看得见 ≠ 今天该做完。否则天天出现天天没做，三天后就是一串欠账，反而更想关掉             |
| 周 / 月 / 长期计划那一眼 | 能看到**整段**：这段时间里同时压着几件事、哪几段挤                                                 |
| 一份还是两份          | **同一份事实、两个距离看**，不存两份（同 4.1 的"一份数据三个出口"）                                     |
| AI 能不能提         | **允许**，做提醒 + 给动力                                                            |
| 怎么提             | **递一个两分钟的小动作**（就是已有的「最小启动步骤」），不是"还剩 6 天、压了 3 件"。以前得你点开才给，现在允许它主动递到"还没开始"的场合 |
| 分寸              | 提醒指向任务、给动力指向人，两者不混成一句；不许空泛鼓励；**赦免权仍在**，防止"常驻 + 会开口"变成天天催                    |

**「完成」怎么算（11-21 补定，此前 5.2 只定了存在形态，没定完成语义）：**

| 什么时候动               | 结果                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| 截止日前随时点「完成了」        | 从今天到截止日所有天里**一起收起**，进「那天做完的事」回顾、算完成率、可给正反馈                                          |
| 到截止日当天还没做           | 第一次落进「今天该做完」，变成正经待办                                                                        |
| 过了截止日还没做           | 按既有逾期口径滚进今天成欠账                                                                              |
| AI 递的两分钟小动作做完了     | **不算完成**，只推进到「进行中」                                                                          |
| 不干了                 | 「跳过」对这类没意义（它不属于任何一天）；彻底放弃走「放弃」                                                    |

界面上常驻带只有两个入口：**「完成了」**和**「先做 10 分钟」**，不搞状态机。  
上面三条语义是**查询口径在 `DueAt` 时间轴上自然滑动**的结果，不是新写的状态机。  
完成率分母 = 清单里"还没做的 + 已经做完的"两段之和（常驻项独立成带，天然不进分母）。  
AI 那边 `date`（安排在哪天做）与 `dueDate`（只有截止日）分成两个字段，二选一；  
常驻项虽不在按天清单里，会单独整段列进系统提示，保证「软件里所有信息 AI 都能看到」不被破坏。

**用户自己也能建（11-22 补）**：日程页底部快速添加区最左边一个「今天 v」按钮，  
点开才浮出四种形态——**今天做 / 定点（带时间）/ 只有截止日 / 每天**——选完收起。  
默认仍是「今天」，随手打字回车不变；定点才展开 `TimePicker`、只有截止日才展开  
`DatePicker`，全部收起时那一行塌成 0 高，所以常驻控件反而比原来少一个。  
四种各走一个专用创建入口（`AddToDayAsync` / `AddDeadlineAsync` / `PerOccurrence`），  
形态由入口写死，界面不碰数据层、不加迁移、不改提示词。  
**没给的两样**：容器 / 阶段性目标（界面已有「大任务」那套 `projects` 壳，两套并存会分不清）、  
「不判成败」（还没定案，且建完不进清单，给入口像没加上）。  
**清单里怎么认得出是哪一种（11-22 晚间补）**：副标题开头给一个词——`定点` / `期限` / `每天`。  
「今天做」不写：这张清单本身就是今天、每条都是今天的，再写一遍是废话，  
还会把本该显示的时间 / 用时挤掉。所以四种仍然可辨——**有「定点」是带钟点、  
有「期限」是只到某天、有「每天」是天天回来，什么都没标的就是今天做**。  
判定收在 `Core/Planning/ItemLabels`，界面和冒烟读同一份；读的顺序是 `CompletionMode`  
先于 `Shape`（「每天」底下 `Shape` 仍是 `DayTask`，反读会说成「今天」）。  
顺带修掉一句假话：库里「每天」的记录原来被显示成「尚未安排时间」——  
它天天都排好了，只是没有钟点。

**「每天」真的每天出现（11-22 晚间接上）**：原先只建当天这一条，第二天打开就找不到了——  
**入口给了却不兑现，比没有这个入口更糟**。现在跨天时会给上一天那条补出今天的新记录  
（`EnsureDailyInstancesAsync`）：`RecurrenceParentId` 串成链、**幂等**（链本身就是  
"已经延续过"的标记，不需要额外游标表）、**只补一天**（三天没打开就补一天，补一串等于  
凭空造出三条"你没做的事"）、**不补不判成败那种**（它本来就不进清单，补了只是每天多一条  
看不见的记录）。昨天那条保持原样，完成记录留在昨天，"上周背了几天"仍查得出来。  
触发点是"取清单前"和"后端启动"，都不是后台任务——少一个后台任务就少一类"它没跑起来"  
的故障（同 `SkippedAt` 那条理由）；另留 `POST /api/items/ensure-daily` 手动补。  
**`RRule` 仍没用上**：这是链式补记录，不是规则展开，所以"提前一个月建好每天的事"还不行。

**实现走过一次弯路，记下来防回退（11-22）：** 第一版图省事，用  
`StartAt == null + DueAt = 截止日最后一刻` 推断「只有截止日」，没加字段。  
结果 `date`（安排在某天）与 `dueDate` 落库后长得一模一样，真实库里 18 条  
「11-22～11-24 按天摊出来的普通待办」全被当成常驻项、显示成「还有 N 天截止」。  
**根因是拿时间字段兼职当分类用**。现在改成 `Shape` 一个强类型字段显式声明形态，  
`Core/Planning/ItemPresence` 第一句就读它；加了 `AddTaskAxes` 迁移，历史记录一律回填成  
「定日」（最保守），**不擅自把任何一条猜成「只有截止日」**。  
项目里早就写过一条规矩：Tags 是给人看的自由标签，有业务含义的分类必须强类型——这次是撞上才补上。

> 一句话记牢：**不是少了个"填截止日"的框，是软件默认"每件事都得属于某一天"。**

### 5.2.1 事情怎么分类：一个显式枚举 + 可空属性 + 父子关系（11-22 收敛）

**这一节的立场改过一次，先摆结论**：分类不是几根能自由组合的坐标轴。库里就是一个显式
枚举 `Shape`（这是什么形态）+ 几个可空属性 / 开关（截止日、钟点、每天反复、不判成败）
+ 一根 `ParentTaskId` 自引用（挂在谁下面）。「是不是容器」读 `CompletionMode.ByChildren`，
「判不判成败」由截止日和今天读出来——都是读出来的结论，不是额外的轴，也不是存进库的字段。

**为什么先写成三根轴、当天又收掉**：11-21 的 18 条误判逼出的是「形态从来没被当成数据存过」，
不是「分类维度不够」。可 11-22 落地时按组合数学搭了三根轴（落哪天 / 是不是容器 / 怎么算完成），
真实库 180 条里 165 条挤在同一格，12 个交叉格子有 3 格定义上填不出，
且「是不是容器」和「按子项汇总」实现里根本是同一个字段 `CompletionMode.ByChildren`，
`ItemAxes` 还给「是不是容器」留了第二个判法（有没有子项）。骨架比实际用法长得快——
又一次「越做越冗余」，只是长在数据结构里、界面上看不见。于是当天又收了一次：
**不推翻重做**，字段、迁移、读判据全留着，收的是叙事与心智模型，顺手清掉空转取值和重复判据。

**三条硬约束，一条都不能退**（跟用不用坐标系无关）：

- **形态必须显式存。** 那 18 条误判的根是靠 `StartAt == null` 猜形态，不是因为用了枚举。
  `Shape` 列与 `AddTaskAxes` 迁移不动，创建入口一律显式写形态，不再让时间字段兼职分类。
- **容器是关系，不是类型值。** 它不进「枚举有哪几个值」这个问题；靠 `ParentTaskId` 自引用
  一层层往下挂。这轮把判据统一到 `ItemAxes.IsContainer`（只读 `ByChildren`），
  删掉了「有没有子项」那第二个答案；大任务详情页也改成按 `Depth` 缩进的递归清单，
  由 `Core/Planning/ProjectTree` 纯函数组装（防环、防丢、只数叶子）。详见 5.3。
- **判成败读出来，不存进去。** 「暂时不判」由 `定段 + 截止日还没到` 推得出来，
  存成字段会和 `DueAt` 打架；只有 `VerdictMode.Never`（一直不判）才需要数据声明。

**读出来的三带**（`ItemAxes.VerdictOf`，不是存在库里的第四根轴）：

| 带 | 例子 | 今天会怎样 |
| --- | --- | --- |
| 今天判 | 今天写作业、DDL 当天 | 进清单、进完成率分母、可以点名催 |
| 暂时不判 | 12-15 交报告（还没到） | 常驻看得见，但不算今天该做完、不进分母、不点名 |
| 一直不判 | 0 点上床睡觉（守住类） | 没有完成按钮、不进分母、不滚欠账、不许念 |

「暂时不判」**不存字段**；重复（每天跑 5km）是 `CompletionMode.PerOccurrence` 这个开关，
不是 `Shape` 的第五个取值，`RRule` 真实展开仍留白。顺序 / 先后依赖不进分类，
阶段先按 `SortOrder` 排。四象限「值不值得」、`Priority`、`Tags`、五态 `Status` 也不在分类里。

**两条口径纠偏（讨论里写错过，按代码落地为准）：**
- 每日任务某天漏做：**进那天的分母，算一次没完成，但不迁移到明天、不滚欠账**。  
  「不进分母」只适用于常驻项 / 容器 / 守住类，别套到每日任务上。
- 「记」和「说」分开：数据侧当天封账、记事实；表达侧默认沉默，要给动力也只说「今天这一次」，  
  不翻旧账、不说「你昨天忘记背单词了」。连续天数 / 断签排行仍是第二节明令不做的东西。

**这轮落地的大任务递归层级**：`ParentTaskId` 自引用启用后，「参加数学竞赛 → 第一章 → 做题 / 真题」
可以一层层挂。启用它的代价是必须同时做到：今日清单只出叶子、进度与完成率只数叶子，
否则父子同时冒出来、重复计数。大任务详情页现在就是一个平铺清单按 `Depth` 缩进：
容器行没有打勾按钮、只显示「下级完成几片叶子」和「往里加」，叶子行保持原样。
AI 那边容器不进清单，单独整段喂进系统提示，保证「软件里所有信息 AI 都能看到」不被破坏。
老的 `projects` 表与 `items` 容器这**两套壳还没合并**，顶层「大任务」是否比「阶段」
多一层「答应自己要了结」的语义，用户也还没拍——这两件是下一轮，不混在这里。

### 5.3 五态、跳过、大任务、撤销 `已做`

- 五态：待办 / 进行中（记 `started_at`，量化启动延迟）/ 完成 / **跳过** / 放弃。  
  跳过是"今天不做，明天回来"，**不计入完成率**；放弃是"这事不做了"。
- 大任务只是容器，进度按子任务汇总，分母不含放弃项。
- **撤销**：AI 一次动作 = 一个批次，永久可撤，独立入口不经过 AI；AI 不能真删。  
  用户自己的操作不做 undo。批量修改全交给 AI 一句话，不做多选界面。
- 「拆解」不占 Tab，并入对话；AI 缺信息要带 guess 预填；算出来的东西（估时/理解/异议）必须显示。

### 5.4 时间账与口径统一 `已做（数据）/ 已定未做（统一）`

三份**性质不同、不该合并**的数据源：

1. **屏幕前**（机器记的）：客观，但只知道你在电脑前；离开电脑做的事记不到。
2. **任务计时**（你点的）：能覆盖离线，但**忘了停就一直涨**。
3. **日结**（每天一份快照）：存下来是为了让"变化"能被比较，不存的话改一条旧任务会让历史全变。

问题不在表，&#x5728;**「今天做了多久」被四个地方各算了一遍**：时间页取并集、日结只算屏幕前减娱乐、  
画像自己按小时切、AI 三个数全塞。**统一算法、不合并数据**——建一个「这一天的账」的入口，  
输出带来源标签的一组数（屏幕前 / 计时 / 重叠 / 并集 / 娱乐 / 按小时），四方都只取字段不再自己算。

这一步是 L1「先读后写」的前提：口径不统一，AI 读到的就是四个互相矛盾的数。  
也能顺带治漏算离线、跨午夜、吃饭被当娱乐、忘暂停这几类同根问题。  
「一天从几点切」留到下一轮单独定（涉及日程页、计划页、提醒二十多处，不跟算法一起动）。

### 5.5 干预引擎 `已做`

情境感知且**双向**：做完 / 休息日给正反馈，没做完温和提示；不阻断，但提示要点一下才消失。  
AI 性格随状态切换；防过量时提异议 + 等二次确认，不擅自拒绝。  
每日额度口径是「**给一件事的**每天上限」，不是全天总量；防排太满靠 AI 看七天清单提异议。

### 5.6 欠账

| 项                        | 状态                              |
| ------------------------ | ------------------------------- |
| 重复日程                     | 字段有（RRule / ExDates）、**零逻辑零界面** |
| Android（M10）             | 未开始；最大的坑是 AI 提示词现在在后端而非共享层      |
| 年 / 月视图、独立「我的」页、提醒反应闭环新表 | 未做                              |

## 六、AI 最终是什么样

### 6.1 它已经是 agent，问题是成熟到哪一级

现有五个**写**工具（create / set_status / reschedule / rename / delete），能真改数据、整批可撤销；  
11-21 又加了第六个动作 `query`（只读、查窗口外某天的清单、不进撤销批次）。  
所以不是"要不要接 AI / 要不要变 agent"，而是**成熟到哪一级**：

```
L0  单轮工具调用    说一句 → 调一次工具 → 整批执行 → 整批撤销      ← 主体仍在这（11-21）
L1  多轮闭环        工具结果回喂；能"先看看再决定"；失败只重做那一步
L2  承诺与待办      它说"我记着"，就真的落一条；下次开口前先翻账
L3  主动执行        不等叫，按时间/事件自己发起行动（现在只说话不动手）
```

L1 才接得住「把这周重排一下，冲突的往后挪」；L2 才接得住「帮我记着这事」；  
L3 的最贵成本不是代码，是**信任**。  
**11-21 的位置**：聊天链路打通了 L1 的第一道门——发只读 `query` → 系统查库 → 结果回喂 →  
再答（最多两轮）。但分步做、失败只重做那一步、撤销从整批变按步都没动，**整体仍算 L0**；  
主动开口链路也还是单轮。

### 6.2 必备能力九项（从实测毛病里长出来，不从"agent 应该很厉害"里推）

**底线三件**（不管到哪级都要修牢，都是小改）`第 1 件时间那一族已做（11-21），2/3 未做`

1. **硬数字代码算**：时间差、时长、完成率由代码算好喂它，提示词只许复述、不许推算。  
   **11-21 时间这一族已落地**：`Core/Ai/ChatTime` 把时段 / 日期标签 / 间隔 / 跨夜算好，  
   聊天与主动开口两条链路共用一份口径；完成率与时长本来就是代码算的（stats）。
2. **说过没的闸**：主动开口落库前查近期是否说过同句 / 同义，防复读。
3. **听得懂拒绝**：岔开话题 = 这个话题到此为止；明示"不想谈" = 当天不再提。

**L1** `第一道门已开（11-21）`　4. 先读后写（`query` 能查窗口外某天的清单，但「查完再动手改」的闭环还没验证）　5. 分步做、失败续做（撤销模型从"整批"变"按步"，工程量最大）  
**L2** `未做`　6. 承诺落账（一张小表，用户可看可删）　7. 开口前翻账  
**L3** `未做`　8. 权限边界（哪些先问、哪些做完再报）　9. 主动发起（接上画像出口 ③）

### 6.3 感知与记忆：另一条轴 `主体仍是讨论存档（11-21 自查开了最窄的一小块）`

阶梯说「它能做到多复杂」，这一条说「**它知道得多全**」。两项纵横关系，不重叠。  
五项其实是同一条河的上中下游：

```
搜索 / 读文件 / 自查   →   记忆   →   兑现
（把信息喂进来）          （留下来）  （变成行动）
```

| 能力                  | 状态      | 要点                                                                        |
| ------------------- | ------- | ------------------------------------------------------------------------- |
| **联网搜索**            | `已定`    | 拆任务需要外部新信息（"现在学 X 该用什么材料"），模型内部是旧世界，不联网只能编。悬着一个决策点：搜索是另一份 key、花钱的动作要不要先确认 |
| **读文件**（pdf / docx） | `已定`    | 把项目结构文档这类"你希望它知道的"直接喂进去据此拆大任务。guess 之所以是 guess，就是因为缺依据                    |
| **记忆**              | `已定`    | 见 4.1 / 4.3                                                               |
| **自查**              | `开了第一道门（11-21）` | 与搜索对偶：搜索查外部世界，自查查**你自己的世界**（时间账、画像、真实可用时段）。现在只读 `query` 能查窗口外某天的**清单**，时间账 / 画像 / 可用时段还只能被动等喂               |
| **兑现**              | `讨论后补入` | **记得 ≠ 做到**。没有这条，记忆只让它变成"很懂你但什么都不做"的朋友                                    |

### 6.4 说话的分寸

语气三档可调（克制 / 温和 / 直接）+ 自定义一句人设 `已做`，**默认克制**（失误代价小）。  
三档共同底线：不许挖苦、不许空泛鼓励。  
AI 主动开口：客户端判断"该不该说"、后端决定"说什么"，必须写进 `chat_messages`；  
一期只说话不改数据；空着的一天不算低完成率。

**七条实测毛病**（留着当验收清单，别重犯）：心算时间差会错 / 承诺悬空 / 同一句复读 5 遍 /  
追问 4 遍听不懂「不想谈」/ 只能整批退 / 知道也推不动（"去吃饭"两小时后还说"饭先吃"，  
时间、在场、历史**全喂了**）/ 视野里没有过去。  
根子一句话：**不是它不知道，是知道也推不动——该代码做的推理留给了模型。**  
> 11-21 状态：心算时间差（时间这一族）、视野里没有过去已修；「知道也推不动」里  
> 隔多久 / 状态是否过期这一半已交给 `ChatTime` 算，其余五条仍欠。清单留着是当验收标准，  
> 不代表还没修——逐条现状看 `AI能力演进.md` 第二、九节。

### 6.5 不变量（任何一级都不许破）

不阻断、不改考核、一切可撤销、AI 不能真删、用画像做减法不做审判、  
AI key 由用户自己填（不预置在服务端、用完即弃、不写盘不打日志）。

## 七、技术形态（只列会影响产品判断的）

- C# 全栈：.NET MAUI（Windows + Android 一套代码）、ASP.NET Core 本地后端、EF Core / SQLite；  
  Android only，不做 iOS。
- 后端只在本机回环地址，由客户端自己拉起；**关客户端后端不消失**。  
  它存在的唯一理由是 AI 要联网、密钥要放在不随程序目录走的地方；时间页 / 日程页直读数据库，不依赖它。
- **离线只读、在线可写**，但数据模型已预留离线可写（version / 墓碑 / 待提交队列）。
- 一期不做服务端推送（国内无 FCM）：Android 本地闹钟 + Windows 本地通知。
- 计算层放 Core / Data，**客户端与后端共用同一份**，Android 将来也调这一层。  
  硬规矩：**任何一个数，只能算一次**。

## 八、离终点还差什么（按依赖顺序，不是催工单）

| # | 事                          | 状态       | 为什么排这儿                                    |
| - | -------------------------- | -------- | ----------------------------------------- |
| 1 | 忘暂停 → 计时段跨夜的**自动收尾**       | `已定未做`   | 每天都在产生脏数据，已手工修过一次；不静默改，写进对话告知且可撤销         |
| 2 | 硬数字代码算 / 说过没的闸 / 听得懂拒绝     | `部分已做`   | 便宜、立刻止血，对应七条实测毛病；11-21 只落地了「时间差」这一族，后两件仍未做 |
| 3 | 口径统一（只搬"时长"这一项）            | `已定未做`   | 第 1 条的长期解，也是 L1 先读后写的前提                   |
| 4 | 主动开口改「每天第一次检测到你在用」+ 分时段文案  | `已定未做`   | 验证期实测：早晨 8–11 点 5 天 0 次触发（那时没起床），战场在下午与深夜 |
| 5 | 只有截止日的事（5.2 第三种形态）         | `已做`（11-21；11-22 改显式声明） | 常驻带 / 三条完成语义 / AI 能建 `dueDate` 都已落地；11-22 起形态由 `Shape` 显式声明、不靠时间字段推断；周月视图「看整段」那一眼仍未做 |
| 6 | L1 多轮闭环 / L2 承诺 / L3 主动执行  | `方向已定；L1 第一道门 11-21 已开` | L1 分水岭（query 回喂已通，分步 / 按步撤销未做）；L3 最贵的是信任 |
| 7 | 感知与记忆五项（6.3）               | `已定，未排期` | 攒够了或某条确定要做时，逐条落实；11-21 只做了「自查」里查清单这一小块 |
| 8 | 重复日程、Android、年/月视图、独立「我的」页 | `部分已做`（「每天」11-22 接上） | 「每天」跨天会补出当天那条（链式补记录、幂等、只补一天）；`RRule` 规则展开、按周的重复、Android、年/月视图仍欠账 |

**11-22 一批批下来留白没做的**：`RRule` 真实展开（现在只有字段与「漏做当天封账」口径）、  
顺序 / 先后依赖、一直不判那类的完整判定与趋势、主动开口链路读画像。历史那 11 条「0点上床睡觉」  
也**没有被擅自重新归类**——迁移只回填最保守的「定日 / 做一次 / 判」，要改得用户自己发话。  
同日凌晨先补了**写的一侧**：对话里 AI 能建「每次各算」和「不判成败」两种记录  
（`repeatsDaily` / `noVerdict`）；当天上午又给**日程页加了折叠的新建入口**（四种形态，见 5.2），  
这一步**推翻了「对话是唯一能改数据的入口」的原定案**——用户不借助 AI 也应能直接建。  
`RRule` 展开没做，所以「每天」不会自动长出后面几天的实例；容器 / 不判成败仍不给**日程页**入口。

**同日第八批（收分类 + 大任务递归层级）**：用户质疑「为什么要搞这么复杂的结构」，
逐格盘过真实库后自己也认了——三根轴大半空转，②和③在实现里是一个字段，
「是不是容器」还有第二个判法。**这轮主要是删，不是加**：字段、枚举、迁移一个没删
（收回事故、留着兼容历史），收的是叙事与心智模型；`AddContainerAsync` 停止写入库里 0 条的
`Unanchored` 空转取值；容器判据统一到 `ItemAxes.IsContainer`；大任务详情页改成按 `Depth`
缩进的递归清单（`ProjectTree` 纯函数 + 一个输入框切「加任务 / 加阶段」+「往里加」）。
冒烟 601 项。**没做的**：两套壳合并、顶层「大任务」的目标语义、`RRule` 展开、`noVerdict` 入口、
界面整体改版（用户提过「UI 有点繁杂」，这轮没碰）。详见 5.2.1。

**同日第九批（把它真的用起来，全是"点了没反应"的地方）**：用户不再是问概念，而是连着报了
五处"用起来不对"。①**AI 说看不到大任务**——查库发现项目名和任务归属根本没进系统提示
（只喂了容器那一段），补 `GetAllWithItemsAsync` 并加一段靠后的【视野校正】，
专治「你现在能看到了吗」这种问它自身状态的元问题；项目下的任务给完整 Guid
（上一版为省 token 给 8 位短 id，模型拿去 `delete` 会找不到记录）。
②**清单里分不清四种形态**——副标题加形态词（见 5.2）。
③**大任务子任务全被排到当天**——`AddAsync` 的"没给时间就兜底到今晚 23:59"被详情页加子任务
踩中，加 `keepNoDueAt`，清单查询同步排除"属于大任务又没定日期"的条目。
④**做完的事没有去处**（用户问「ddl 完成了之后去哪里了」）——分成 `DoneItems` 一段挂在清单底部，
完成率分母改成"未完成 + 已完成"，全做完时不再弹"今天还没有安排"。
⑤**鼠标滚轮滚不动**——Windows 上 `CollectionView` 在 `ItemsSource` 为空时 Header/Footer
不参与滚动，整块改成单一 `ScrollView` + 四段（行模板提到 `Resources` 两段共用）。
外加**「每天」真接上**（见 5.2）。冒烟 601 → **653 项**。
**新增留白**：没有"停止这个每天任务"的入口；`RRule` 仍未展开；`docs/` 之外没动别的东西。

**顺序里的硬依赖**：底线三件 → 口径统一 → L1（自查、兑现分别是 L1「先读后写」和  
L2「承诺落账」的感知侧，可并行）→ L2 → L3。  
没有搜索和自查，L1 的"先看看"看的是旧世界；没有记忆，L2 的"说到做到"没有账可记。
